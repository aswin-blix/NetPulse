NetPulse 1.0 — development notes

Runtime: Python 3.10+ with Tk, Windows 10/11 x64.
No third-party runtime modules are required. Python calls the Windows IP
Helper API directly, so psutil is unnecessary in this implementation.

Run from this folder:
  python app.py
  python app.py --config C:\some-folder\settings.json

Validate from this folder in a Windows desktop session:
  python -m unittest discover -s tests -v
  python -m pip install ruff==0.16.10
  python -m ruff check .
  python -m ruff format --check .

Build with a standard python.org Python installation containing Tcl/Tk:
  python -m pip install pyinstaller==6.22.3
  python -m PyInstaller --clean --noconfirm --onefile --windowed --name NetPulse --icon NetPulse.ico --add-data "NetPulse.ico;." app.py
The portable executable is then dist\NetPulse.exe.

FILES
app.py: Tk widget, customization panel, input bindings and polling.
network.py: native Windows adapter metadata, counter sampling and SI formatting.
settings.py: validated JSON preferences with atomic replacement.
windows.py: DPI awareness, work-area placement, rounded window and single instance.
tk_runtime_hook.py: canonical Tcl paths for unusual Windows profile mappings.
tests/: deterministic counter tests, settings tests, and Tk integration tests.

MEASUREMENT DESIGN
GetIfTable2 supplies the cumulative InOctets/OutOctets counters.
GetIfTable2 allocations are freed with FreeMibTable in all paths.
Counter subtraction occurs as integers before division by monotonic elapsed
time, preserving precision for large 64-bit totals.
Samples are discarded and rebased after interface changes, counter decreases,
nonpositive timestamps, or gaps exceeding 10 seconds. Read failures display
unavailable, reset the baseline and retry at the normal polling interval.
Automatic selection excludes virtual layers to avoid VPN double counting.
No packets or network requests are generated by the application itself.

Official API references:
https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getiftable2
https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_if_row2

DESIGN
Default compact window: 260 x 120 logical pixels; 260 x 102 without graphs.
Mini: 226 x 38 logical pixels, with only the two speed readings.
Mini has no header or buttons; right-click for settings and exit.
Comfortable: 120% of the compact size.
Windows display scaling can increase physical pixel dimensions.
Corner radius is adjustable from 0 to 24 logical pixels (default 12).
Zero removes the rounded window region. Nonzero values scale with the widget
and clamp to half its width/height; Win32 receives twice that radius as the
corner ellipse diameter. Existing preferences without this field retain
the previous 12-pixel appearance. Reset defaults restores 12 pixels.
Dark/light palettes are paired with high-contrast accent and upload colors.
Preferences change immediately and persist on updates, drag release and exit.
Off-screen saved positions are moved into an available monitor work area.

SCOPE
No tray integration, automatic startup registration or bandwidth-capacity test.
Rates include LAN traffic; no per-process or Internet-only packet filtering.
Moving across monitors with different DPI values may need a restart for
optimal scale; the initial Windows DPI is used for widget sizing.
Canvas readings are visual; they do not expose full screen-reader semantics.
